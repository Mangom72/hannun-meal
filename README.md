# 한눈급식

학교를 한 번 선택하면 한국 시간의 생활 일정에 맞춰 급식을 보여 주는 네이티브 Android 앱입니다. Cloudflare Workers를 통해 NEIS 급식을 받고 GitHub Pages의 전국 학교 목록을 기기에서 검색하며, 로그인·광고·분석 SDK를 사용하지 않습니다. 내려받지 못한 날짜에 임의 메뉴를 만들어 표시하지 않습니다.

**[최신 APK 내려받기](https://github.com/Mangom72/hannun-meal/releases/latest/download/hannun-meal.apk)** · [릴리스 기록](https://github.com/Mangom72/hannun-meal/releases)

1.2.1부터 학교만 선택하면 공식 데이터 서비스에 연결됩니다. 홈·상세·검색·위젯과 그릇 아이콘을 개선했으며 공개 릴리스의 자동 업데이트에는 로그인이나 개인 토큰이 필요하지 않습니다. 기존 정식 서명키와 사용자 설정을 유지합니다.

## 주요 기능

- 학교명 검색, 주소 및 교육청·학교 코드 확인, 학교 변경
- 오늘의 급식·날짜 탐색·주간 전체 메뉴, 월–일 또는 다음 허용 등교일 5일 보기
- 시간 구간별 오늘/최대 20일 후의 조식·중식·석식 또는 다음 가능한 식사 선택
- 요일·식사 종류 제외, 결식 건너뛰기/선택 유지, 수동 탐색 후 자동 복귀 또는 유지
- 전환 시간과 독립적인 실제 식사 예정 시간, 남은 시간 표시
- **다음 급식 / 하루 급식 / 주간 선택 급식 / 주간 전체 급식** 위젯 4종
- 위젯 ID별 학교·규칙·주간 범위·표시 정보·색상·불투명도·글자 크기 설정
- Room 오프라인 캐시, DataStore 설정, WorkManager 자동 동기화
- GitHub 공개 릴리스 자동 확인·다운로드·서명 검증 후 설치 안내
- 한국어 Material 3, 시스템/밝은/어두운 테마, Android 12+ 동적 색상, 3가지 색상 프리셋
- 메뉴·열량·영양·원산지·알레르기 번호·NEIS 원문 상세 보기

최소 Android **8.0(API 26)**, compile/target **API 36**. 앱 위젯은 Compose를 넣지 않고 `AppWidgetProvider`와 `RemoteViews`로 구현합니다.

## 빌드 및 설치

필요한 도구는 **JDK 17 이상(컴파일러 포함)**, Android SDK Platform 36, Build Tools 35.0.0입니다. AGP 8.13.2 / Kotlin 2.2.21 / Gradle 8.13을 사용합니다. Android Studio에서 저장소 루트를 열어 SDK를 설치할 수도 있습니다.

`local.properties`에 본인의 SDK 경로를 적습니다(이 파일은 Git에서 제외됩니다).

```properties
sdk.dir=/absolute/path/to/Android/Sdk
```

```sh
./gradlew testDebugUnitTest lintDebug assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

APK의 표준 출력 경로는 `app/build/outputs/apk/debug/app-debug.apk`입니다. NEIS 키 없이도 앱을 컴파일·테스트·설치할 수 있습니다. 앱의 데이터 연결에는 배포된 Worker/Pages 공개 주소가 필요합니다. 프로젝트의 `.tools/`는 이번 클라우드 실행에서만 사용한 로컬 도구이며 소스 배포에는 필요하지 않습니다. 프록시가 있는 조직에서는 Gradle의 JVM 프록시 설정과 조직의 CA 신뢰 저장소를 사용하세요. TLS 검증을 끄지 마세요.

## 데이터 서버 연결 (1.2.0)

NEIS 인증키 한 개를 **Cloudflare Worker Secret과 GitHub Actions Secret**에 같은 값으로 저장합니다. 앱/JavaScript/Pages/APK에 키를 넣지 않습니다. 기존 개인 NEIS 키 항목은 업데이트 시 제거하며 학교·시간 규칙·위젯·캐시는 유지합니다.

- 학교 검색: 주간 Actions가 생성한 전국 초·중·고 목록을 Pages에서 내려받아 기기 안에서 부분 이름/지역/학교급으로 검색합니다. 타이핑마다 NEIS를 부르지 않습니다.
- 급식: Worker의 `GET /v1/meals/{office}/{school}/{YYYYMM}`로 월 전체를 받습니다. 기존 Room 저장과 메모리 캐시를 재사용하고 Worker edge 캐시가 NEIS 요청을 줄입니다. 실패는 정상 빈 급식과 구분하며 기존 캐시를 지우지 않습니다.
- 현재 저장소는 **기존 Android 앱**이며 웹 프런트엔드/PWA는 없습니다. 이번 변경에서 별도 앱을 만들지 않았습니다. Pages는 학교 JSON 호스팅용입니다.

일반 사용자는 서버 주소나 API 키를 입력하지 않습니다. 공식 공개 주소는 `backend.properties.example`에 기본값으로 제공됩니다. 개발자가 자체 서비스를 사용할 때만 Git 제외 `backend.properties` 또는 같은 이름의 환경 변수로 빌드 주소를 바꿀 수 있습니다. NEIS 키는 Worker와 학교 목록 Actions Secrets에만 둡니다.

전국 학교 목록은 17개 교육청/초·중·고 **12,060개**를 검증했습니다. 문자 포함 국립학교 코드도 지원하며, NEIS 조회 코드가 없는 원본 32행은 임의 ID를 만들지 않고 제외합니다. 자세한 구조는 [데이터 계층](docs/DATA-MIGRATION.md), 운영 준비는 [배포 문서](docs/DEPLOY-DATA.md)를 참조하십시오.

```sh
npm ci --prefix backend --ignore-scripts
npm --prefix backend test
npm --prefix backend run check
python3 -m unittest discover -s scripts/tests -v
```

## 자동 선택 규칙

기본값은 **Asia/Seoul** 기준입니다. 기기 시간대가 바뀌어도 학교 급식 날짜는 한국 시간을 따릅니다.

| 시간 구간 | 선택 |
| --- | --- |
| 00:00–08:00 | 오늘 조식 |
| 08:00–13:00 | 오늘 중식 |
| 13:00–19:00 | 오늘 석식 |
| 19:00–24:00 | 내일 조식 |

구간 시작은 포함하고 끝은 포함하지 않습니다. **자동 전환** 화면에서 시간 버튼을 눌러 수정하고, 구간을 나누거나 앞 구간에 합칠 수 있습니다. 겹침·빈 구간·잘못된 값이 있으면 저장하지 않습니다. 시작이 끝보다 늦으면 자정을 지나는 구간입니다. 하루 전체는 00:00–24:00으로 표현합니다.

토·일은 기본 제외입니다. 금요일 19:30에 내일 조식을 요청하면 다음 허용일인 월요일부터 찾습니다. 모든 요일이나 식사 종류를 끄면 경고를 표시하고 탐색을 중단합니다. 고정 종류 모드에서는 지정한 식사 종류만 찾습니다.

기본 결식 정책은 **성공적으로 조회했으나 해당 식사가 없는 경우에만** 다음 허용 급식을 찾는 것입니다. 선택 유지 정책에서는 등록 없음 상태를 보여 줍니다. 미조회 날짜에서는 탐색을 멈추고 추가 동기화를 요청합니다. 실패·미조회·확정 결식·오래된 캐시는 구분합니다. 검색은 요청 시작일로부터 21일까지만 진행합니다. 시간 규칙이 미래 날짜를 지정하는 경우 필요한 범위를 추가 조회합니다.

실제 식사 시간의 기본값은 조식 07:30 / 중식 12:00 / 석식 17:30입니다. 이 설정은 메뉴 전환 시각과 독립적입니다. ‘다음 식사’ 모드는 예정 시간이 아직 지나지 않은 식사부터 찾습니다.

날짜 탐색은 임시 수동 선택으로 저장합니다. 기본적으로 다음 규칙 경계·식사 시각·자정에 자동 일정으로 복귀합니다. ‘탐색 후 자동 일정으로 복귀’를 끄면 자동 버튼을 누를 때까지 유지합니다.

## 위젯 추가 및 설정

홈 화면 빈 곳을 길게 누르고 **위젯 → 한눈급식**에서 원하는 위젯을 선택합니다. 지원 런처에서는 앱의 ‘내 위젯’ 화면에서 추가할 수도 있습니다. 런처의 고정 추가 동작에 따라 먼저 기본 위젯이 보일 수 있으므로 위젯의 **설정**을 눌러 완료하세요.

위젯 설정은 각 AppWidget ID에 저장됩니다. 새 위젯은 앱 기본값을 복사하며, 이후 앱 기본값 변경이 기존 위젯 설정을 덮어쓰지 않습니다. 다른 학교, 중식만 표시, 다음 등교일 5일 등으로 각각 구성할 수 있습니다. 위젯 삭제 시 해당 ID의 설정을 제거합니다.

- 메뉴/제목 누르기: 해당 학교·날짜의 상세 메뉴 또는 주간 화면
- `‹` / `›`: 허용된 이전·다음 식사(하루 위젯은 날짜, 주간 위젯은 7일)
- **자동**: 수동 탐색을 초기화하고 자동 일정으로 복귀
- `↻`: 네트워크 동기화 요청
- **설정**: 해당 위젯만 다시 구성

작은 크기에서는 탐색 버튼, 학교 이름, 상태 및 카운트다운을 줄여 메뉴와 설정 진입을 우선합니다. 전체 정보는 위젯을 눌러 확인합니다. 주간 메뉴는 공간에 맞춰 요약하며, 모두 들어가지 않으면 ‘N일 더 · 전체 보기’를 제공합니다. 글자를 무리하게 축소하지 않습니다. 크기와 지원 동작은 런처에 따라 다릅니다.

표시 프리셋은 최소·표준·자세히·직접 설정입니다. 날짜, 요일, 학교, 식사 종류, 식사 시간, 카운트다운, 열량, 알레르기, 마지막 동기화, 다음 메뉴, 최신 상태를 선택합니다. 다음 메뉴 미리보기와 일부 부가 정보는 충분한 공간이 있을 때 표시됩니다.

## 백그라운드·카운트다운 제한

네트워크 동기화는 기본 6시간(설정에서 1/3/6/12/24시간) 주기로 WorkManager에 예약합니다. 기본 요청 범위는 과거 7일–미래 21일이며 날짜 탐색 시 범위를 확장합니다. 같은 학교·월의 요청은 합치며, 성공한 월 전체를 서버 freshness 시각까지 재사용합니다. 네트워크 실패는 지수 백오프로 최대 3회 재시도하고 인증 실패·확정 결식은 즉시 재시도하지 않습니다.

위젯 전환은 캐시에서 다시 선택하여 렌더링하며 정상적으로 캐시가 있는 전환에는 API 요청이 없습니다. 규칙 경계·식사 시각·자정에 **부정확 알람**을 예약하고 15분 주기의 로컬 WorkManager 갱신을 보완 수단으로 사용합니다. 추가·크기 변경·설정 변경·동기화·부팅·날짜/시각/시간대 변경에도 갱신합니다.

Android Doze, 배터리 절약, 제조사 정책, 강제 종료와 런처 상태에 따라 작업과 알람은 지연됩니다. 초 단위 또는 정각 전환은 보장하지 않습니다. 정확 알람 권한·지속적인 포그라운드 서비스·초당 폴링을 사용하지 않습니다. 강제 종료한 앱은 사용자가 다시 열기 전까지 갱신되지 않을 수 있습니다.

기본 카운트다운은 ‘갱신 기준’이라는 표시와 함께 정적으로 갱신해 음수 표시를 방지합니다. 위젯 설정에서 초 단위 라이브 카운트다운을 켜면, 공간이 충분한 다음 급식 위젯의 24시간 이내 남은 시간은 네이티브 `Chronometer`로 표시합니다. 기준값은 `elapsedRealtime`과 목표 시각의 차이로 계산합니다. 24시간 이상은 일·시간 단위 정적 표시, 작은 크기에서는 상세 화면으로 안내합니다. 렌더링 시 이미 지난 식사 시간은 경과 상태를 표시하거나 숨깁니다. 라이브 표시에는 ‘−는 경과’를 명시합니다. 네이티브 Chronometer는 0에서 앱을 깨우지 않으므로 갱신 지연 중 0을 지나 음수로 표시되면 예정 시각 이후 경과 시간이며 남은 시간이 아닙니다. 0초 자동 정지가 필요하면 기본 정적 표시를 사용하세요. 자동 메뉴 전환과 카운트다운 종료는 별개입니다.

## 오프라인과 데이터 관리

Room에 학교·날짜·식사 종류의 복합 키로 메뉴를 저장하고 날짜별 성공 조회 시각과 마지막 오류를 따로 기록합니다. API 실패 시 기존 메뉴를 삭제하지 않습니다. 데이터가 24시간 이상 되었거나 요청에 실패하면 상태를 표시합니다. 한 번도 조회하지 않은 날짜는 ‘미조회’이며 결식으로 처리하지 않습니다. 직접 캐시를 지우면 다음 성공 조회 전까지 오프라인 메뉴를 볼 수 없습니다.

앱 기본 설정 초기화와 캐시 삭제에는 확인 창이 있습니다. 기본 설정 초기화는 개인 API 키와 기본 학교를 지우며, 기존 위젯 설정과 캐시는 유지합니다. 앱 삭제 시 전체 로컬 데이터가 삭제됩니다.

## 테스트·구조·검증 범위

```sh
./gradlew testDebugUnitTest
./gradlew lintDebug
./gradlew assembleDebug
```

선택 엔진 경계값, 제외 요일/식사, 윤년, 미조회/결식/실패, 규칙 검증, 수동 복귀, 타임존, 카운트다운, Retrofit MockWebServer 페이지네이션, 실제 응답 캡처 파싱, Room 다중 학교·오프라인 보존, DataStore 위젯 독립성을 검사합니다.

초기 1.0.0에서 61개 테스트를 검증했고, 업데이트를 추가한 1.1.0은 82개 Android 단위 테스트와 Python 배포 도구 테스트 7개를 검증했습니다. 이는 이전 버전 기록입니다. 1.2.0의 최신 결과는 [이전 검증](docs/TESTING-1.2.0.md)과 [테스트 문서](docs/TESTING.md)를 참조하세요.

자세한 구성은 [아키텍처](docs/ARCHITECTURE.md), 실제 명령 결과와 실기기 확인 절차는 [테스트 문서](docs/TESTING.md)를 참조하세요. 개인 키를 사용한 인증 조회 및 런처별 배치는 기기에서 확인해야 합니다.

## 정식 서명과 자동 업데이트

[배포 안내](docs/RELEASING.md)에 공개 저장소·원래 서명키·Actions Secrets·정식 릴리스 절차를 정리했습니다. 키를 소스나 APK에 넣지 않습니다.

앱 **설정 → 앱 업데이트**에서 자동 확인·자동 다운로드·Wi-Fi 조건을 선택할 수 있습니다. 저장소·토큰 입력은 필요하지 않습니다. 12시간 주기로 공개 릴리스를 확인하고 APK 해시·패키지·버전·SDK·기존 서명을 검증한 뒤 Android 설치 화면으로 연결합니다. 마지막 설치는 사용자의 확인이 필요합니다.
