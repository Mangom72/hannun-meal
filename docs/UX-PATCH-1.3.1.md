# 1.3.1 급식 탐색·접근성 개선 검증

기준 버전은 공개 1.3.0입니다. 기존 Android/Compose 구조, 테마 팔레트, 저장 형식과 서명키를 유지했습니다. 이번 작업에서 Worker나 학교 목록 서비스를 변경하지 않았습니다.

## P0: 데이터 경로와 확인된 결함

### 주간 급식 중복 의심

원본 참고 스크린샷은 이번 작업에 제공되지 않았습니다. API → 정규화 → Room → 화면 경로를 확인했으나, 보고된 반복 중식·메뉴와 결식의 동시 표시는 재현하지 못했습니다. 긴 화면 캡처 때문이라고도 단정하지 않습니다.

- Worker는 동일 날짜·식사 유형의 같은 응답만 합치며 충돌하는 내용은 거부합니다.
- Android 월 응답은 학교·월과 `(날짜, 식사 유형)`의 유일성을 검증합니다.
- Room은 학교·날짜·식사 키를 구분합니다. 실패한 요청이 기존 메뉴나 성공 조회 시각을 삭제하지 않습니다.
- 동일 메뉴명이라도 알레르기 번호가 다른 항목은 보존합니다. 새로운 임의 중복 제거는 추가하지 않았습니다.
- `MonthlyDataTest.kt`, `MealIntegrityTest.kt`에 중복·충돌 응답 거부, 캐시 보존, 학교·날짜·유형 분리, 늦은 타 학교 응답과 네 가지 조회 상태의 회귀 검사를 추가했습니다.

### 수동 날짜가 재시작 후 바뀌는 문제 — 재현·수정

테스트 학교의 10월 31일 토요일 조식을 직접 선택하면 해당 메뉴가 보이지만, 앱을 종료 후 다시 열면 11월 2일 월요일 조식으로 바뀌었습니다. 화면의 임시 탐색 상태는 지정 날짜를 표시했지만, 저장된 수동 선택을 복원하는 엔진은 자동 선택용 제외 요일·식사 필터를 적용하고 있었습니다.

- `domain/selection/MealSelector.kt`: 유효한 수동 선택은 지정 날짜·유형 한 건만 조회합니다. 등록 없음·미조회·실패를 다른 날짜의 메뉴로 대체하지 않습니다.
- 자동 복귀 시점부터 기존 AUTO 규칙을 그대로 적용합니다. NEXT/FIXED 선택 및 위젯의 이전·다음 탐색 알고리즘은 변경하지 않았습니다.
- `ui/LayoutSystem.kt`, `ui/MealApp.kt`: 수동 요청 실패에서도 수동 식사 유형을 유지하며, 만료 시점에는 기존 자동 복귀 표시를 따릅니다.
- 회귀 테스트를 먼저 실행해 **40개 중 신규 5개 실패**를 확인한 뒤 수정했고, 같은 선택 엔진 테스트를 통과시켰습니다.
- 최종 정식 서명 로컬 APK에서 네트워크 차단·강제 종료·재실행 후 같은 토요일 메뉴를 유지하고, 명시적으로 자동 복귀하면 기존 규칙대로 월요일을 선택하는 것을 확인했습니다.

## P1/P2: 화면과 접근성

- `ui/MealApp.kt`: 실제 표시 날짜의 오늘·내일·과거/미래 관계, 자동·수동 선택 상태, 달력 진입을 표시합니다. 설정된 식사 시각은 실제 배식 시각으로 오인하지 않도록 ‘식사 예정’으로 안내합니다.
- 오늘·주간의 ‘알레르기·상세’ 동작에 날짜·식사 이름을 포함합니다. 간결한 메뉴 설정에서도 접근할 수 있습니다.
- 주간은 등록된 메뉴만 상세를 열고, 미조회는 내려받기, 실패는 재시도를 제공합니다. 확정 결식에는 불필요한 상세 버튼을 표시하지 않습니다.
- `ui/MealComponents.kt`: 학교 제목에 학교 변경 동작 이름을 추가하고, 상세에 알레르기 번호가 없다고 유발 식품이 없음을 의미하지 않는다는 안내를 추가했습니다. 공식 번호·식품명·원문은 유지합니다.
- `ui/SettingsScreens.kt`: 모드별 설명, 자동 선택에만 적용하는 제외 항목 안내, 이름 있는 슬라이더, 설정 선택 영역의 최소 높이·줄바꿈 간격을 보완했습니다. 설정 스키마는 변경하지 않았습니다.

수동 날짜 결함 발견 전 전체 검사도 통과했지만, 엔진을 수정했으므로 최종 전체 Android 검사를 다시 수행했습니다. backend·배포 도구 소스는 그 사이 바뀌지 않아 통과 결과를 재사용했습니다.

고정 팔레트 3종 × 밝음/어두움에서 실제 사용하는 텍스트 역할의 대비 4.5:1 이상, 주요 조작 아이콘·outline과 인접 surface의 비텍스트 대비 3:1 이상을 테스트했습니다. 장식 구분선은 조작 경계로 취급하지 않았습니다. 동적 시스템 색상의 모든 조합을 측정했다는 뜻은 아닙니다.

## 화면·상호작용 확인

- 독립된 API 36 테스트 에뮬레이터에서 공개 1.3.0과 정식 서명 로컬 1.3.1을 비교했습니다. 실제 사용자 기기나 기존 AVD 데이터를 삭제하지 않았습니다.
- 실제 학교 자료는 검증용으로 선택한 국립공주대학교사범대학부설고등학교 자료이며, 사용자의 소속 학교로 가정하지 않습니다.
- 320dp·360dp 휴대폰과 1280dp 넓은 화면, 밝은·어두운 테마, 라벤더 프리셋을 확인했습니다.
- 앱 글자 140%와 시스템 글자 130%를 함께 적용해 오늘·주간의 스크롤과 상세 진입을 확인했습니다. 좁은 화면의 날짜 줄바꿈과 긴 학교명 생략은 남아 있지만 조작이 겹치거나 상세 진입이 차단되지는 않았습니다.
- 오늘 화면의 완전히 보이는 활성 조작 영역을 UI hierarchy로 측정했으며 48×48dp 이상이었습니다. 이는 Android 권장 크기 검사이며 웹 WCAG의 타깃 크기 기준과 동일한 기준이라고 주장하지 않습니다.
- 오프라인에서 성공 조회된 빈 날짜와 미조회 날짜를 구분하고, 미조회에는 날짜가 포함된 내려받기 동작이 표시되는 것을 확인했습니다.
- 정식 서명 APK 교체 후 학교·테마·캐시 유지, 간결한 메뉴에서도 상세 진입, 실제 알레르기 번호와 안전 안내를 확인했습니다.

비교 PNG/XML과 실행 로그는 Git 제외 로컬 경로 `artifacts/ux-patch-20261031/`에 보관합니다. `baseline/`은 공개 1.3.0, `after/`는 화면 변경 검증, `final/`은 최종 수동 날짜 수정 후 검증입니다. 이 경로는 공개 이미지 링크가 아닙니다.

## 남은 확인

TalkBack 음성 탐색·실제 포커스 순서, 물리 기기의 제조사별 절전·야간·재부팅 갱신, 런처별 위젯 배치와 모든 동적 색상 조합은 이번 검증으로 보장하지 않습니다. 위젯은 기존 렌더링·설정 회귀 검사와 실제 미리보기로 확인했으며, 모든 런처의 배치를 다시 검사한 것은 아닙니다.

업데이트는 공개 GitHub 릴리스를 통해 제공하며 마지막 설치는 Android 시스템 화면에서 사용자가 확인합니다. 자동 확인 시각은 절전 정책 등에 따라 지연될 수 있습니다.
